# لوحة المدير (المرحلة 8)

## تعيين أول مدير (T8.1)

القواعد تمنع أي مستخدم من ترقية نفسه، فأول مدير يُعيَّن يدوياً من Firebase Console:

1. سجّل الدخول في التطبيق بالحساب المراد ترقيته، ليُنشأ مستنده في `users`.
2. افتح Firebase Console ← Firestore Database ← المجموعة `users`.
3. اختر المستند الذي يطابق بريد الحساب، وغيّر الحقل `role` من `user` إلى `admin`.
4. حدّث صفحة التطبيق؛ يظهر رابط «لوحة المدير» في القائمة الجانبية، والمسار `/admin`.

بعد ذلك يرقّي المدير غيره من جدول المستخدمين، ولا يستطيع نزع دوره هو، فلا تبقى المنصة بلا مدير.

## محتوى اللوحة

- **الإحصاءات (T8.3):** عدد المستخدمين والمشاريع والتحليلات والقوالب بـ `getCountFromServer`، فلا تُنزَّل المستندات.
- **المستخدمون (T8.2):** جدول مع بحث بالاسم أو البريد، وتغيير الدور.
- **القوالب (T8.4):** أمثلة جاهزة في المجموعة `templates` تُضاف وتُعدَّل وتُحذف وتُنشر. المنشور منها يظهر للمستخدمين في نافذة «مشروع جديد» بلغة المخرجات المختارة، وإن لم يوجد قالب منشور بتلك اللغة يظهر زر «جرّب مثال المكتبة».

## صلاحيات المدير في قواعد الأمان (T8.5)

| المورد | ما يحق للمدير |
| --- | --- |
| `users` | القراءة، وتغيير حقل `role` وحده لغيره، والحذف |
| `projects` | قراءة مستند المشروع (لازم للعدّ)، دون التعديل أو الحذف |
| المجموعات الفرعية للمشروع | `analyses` للقراءة فقط (لازم لعدّ التحليلات)، ولا يقرأ `diagrams` و`databaseDesigns` و`reports` |
| `templates` | الكتابة كاملة؛ وغير المدير يقرأ المنشور فقط |
| `usage` و`settings` | كما كانت |

## الاختبار

```bash
# اختبارات غير المدير فقط
npm run test:rules

# مع اختبارات المدير: حساب مدير موجود
ADMIN_EMAIL=you@example.com ADMIN_PASSWORD=... npm run test:rules
```
